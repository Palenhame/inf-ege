# Frontend.md — Техническая спецификация Фронтенда (React 19 SPA)

Данный документ описывает архитектуру клиентского приложения в папке `frontend/`, модернизацию текущего кода, устройство встроенных рабочих инструментов КЕГЭ (Python IDE + OPFS, Табличный процессор Excel, Рисовалка) и реактивную связку WebSockets с кэшем данных. Все сетевые вызовы и форматы сообщений строго соответствуют `Contract.md`.

---

## 1. Ревизия стека и очистка существующего `frontend/`

### 1.1. Почему чистое реактивное SPA без Node.js SSR
- Приложение построено вокруг постоянных `client-only` движков: WebSocket-мультиплексор, Web Worker с Pyodide (`SharedArrayBuffer`), Ruff WASM, Canvas-таблицы `Univer` и оверлей рисования `perfect-freehand`, которые не должны разрываться или перемонтироваться при навигации.
- Раздача статики напрямую через внутренний Nginx проекта с заголовками `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: require-corp` гарантирует стабильную работу `SharedArrayBuffer` во всех браузерах.

### 1.2. Что удаляем из текущего `package.json`
Выполнить чистку неиспользуемых и дублирующихся зависимостей:
- **Удалить**: `react-py`, `xterm`, `xterm-addon-fit`, `@xterm/addon-fit`, `react-rnd`, `react-router`.
- **Сохранить и развить уже написанные сильные модули**:
  - `DraggablePanel.tsx` (плавающие докающиеся к краям экрана окна).
  - `tldrawLayer.tsx` + `overlay.tsx` (рисование поверх экрана с `perfect-freehand`, каллиграфией, ластиком и историей `Ctrl+Z/Y`).
  - `editor/` (`Monaco Editor` + `Ruff WASM` + кастомный `terminal.tsx` + трекинг вставленных кусков `pasteRangesRef`).
  - `devtools-detector` + `themeStore.ts` + UI-кит `shadcn/ui` на Tailwind CSS v4.

### 1.3. Целевой стек пакетов (Установить и настроить)
- **Роутинг**: `@tanstack/react-router` (100% строгая типизация search-параметров URL для фильтров Банка, табов групп и открытых модалок ученика!).
- **Серверный стейт и кэш**: `@tanstack/react-query` v5 (с точечным патчингом кэша из входящих WebSocket-событий).
- **Клиентский UI-стейт**: `zustand` v5 (тема, режим роли `student | teacher | admin`, `impersonatedUser`, состояние окон IDE / Рисовалки / Таблиц, локальное хранилище черновиков кода в Банке).
- **Табличный процессор (встроенный Excel/Calc для №3, 9, 18, 22)**:
  - `@univerjs/presets`, `@univerjs/preset-sheets-core` (Canvas-движок электронных таблиц с формулами, фильтрами, сортировкой, закреплением строк и мгновенным подсчётом `СУММ / СРЗНАЧ / КОЛИЧЕСТВО` в статус-баре при выделении диапазона — критично для быстрого решения №9 и №18!)
  - `xlsx` (SheetJS) — конвертация `.xlsx` / `.ods` / `.csv` файлов задачи в книгу `IWorkbookData` и обратно.
- **Локальная файловая БД в браузере**: `idb-keyval` (или `idb`) + нативный **OPFS (`navigator.storage.getDirectory()`)** для хранения скачанных файлов задач и изменённых пользователем таблиц.
- **Высокопроизводительные таблицы и списки**: `@tanstack/react-table` v8 + `@tanstack/react-virtual` (виртуализация списка Банка задач и Live-матрицы класса `40 × 27`).
- **Рендеринг условий и формул**: `react-markdown`, `remark-gfm`, `remark-math`, `rehype-katex`, `katex`.
- **Формы, схемы и QR-коды**: `react-hook-form`, `zod`, `@hookform/resolvers`, `qrcode.react` (генерация QR-кода инвайта в группу на проектор).
- **Графики аналитики**: `recharts` (компоненты графиков `shadcn/ui`) + кастомный интерактивный SVG/Canvas компонент `ProctoringTimeline`.

## 3. Детальная реализация ключевых систем Фронтенда

### 3.1. Апгрейд Python IDE, локализация WASM и умный файловый менеджер (Pyodide + OPFS)

1. **Отказ от внешних блокируемых CDN в продакшене**:
   - Обновить `py-worker.js` с `v0.25.0` до актуального **Pyodide `v0.27+` (Python 3.12)**, чтобы ученикам были доступны все современные конструкции языка (`match/case`, `itertools.batched`, быстрые f-строки и сообщения об ошибках Python 3.12).
   - Скрипт сборки кладёт дистрибутив ядра Pyodide + колесо `jedi` (только стандартная библиотека Python без сторонних пакетов `numpy`/`pandas`, `sys` и др. доступны из коробки) и `ruff_wasm_bg.wasm` в `public/vendor/`, чтобы внутренний Nginx раздавал их мгновенно с того же домена (`COEP: require-corp` никогда не сломается даже в закрытых школьных сетях!).

2. **Умная работа с файлами задачи и порог `5 МБ` (`FileCacheService` на OPFS / IndexedDB)**:
   - Когда ученик открывает задачу (в Банке или в Тесте/Пробнике), её список `files` передаётся в контекст рабочего места.
   - **Единый локальный кэш**: если ученик нажал кнопку «Скачать» возле файла на карточке задачи, файл скачивается с `ReadableStream` прогрессом, отдаётся браузеру на диск **и одновременно сохраняется в OPFS** по ключу `task-file-{taskId}-{fileId}`. Если файл уже есть в OPFS — повторно по сети он не качается!
   - **Прокидывание в виртуальную ФС Pyodide (`/home/pyodide/{file.name}`)**:
     - Для всех файлов задачи размером **`<= 5 МБ` (`5 * 1024 * 1024` байт)**: при открытии задачи/IDE файл автоматически подтягивается (из OPFS или по сети с отображением аккуратного прогресс-бара в шапке IDE: *«Загрузка 17.txt в Python: 68%»*) и передаётся в `py-worker.js` (`pyodide.FS.writeFile(filename, uint8Array)`). Ученик сразу пишет `open('17.txt')` безо всяких путей!
     - Для тяжёлых файлов **`> 5 МБ`** (типичный `27_B.txt`): автозагрузка не стартует молча. В шапке IDE и возле файла выводится компактная плашка: *«Файл 27_B.txt (24.5 МБ) не загружен в интерпретатор — [Загрузить в Python]»*. По клику идёт потоковая загрузка с процентами в OPFS + монтирование в `pyodide.FS` (если файл уже лежал в OPFS после скачивания — монтируется за `< 50 мс` без сетевого запроса!).

3. **Хранение кода ученика**:
   - В **Банке задач**: код в `editorStore` сохраняется в `localStorage` отдельно под каждый `taskId` (`bank_code_{taskId}`), чтобы при переходе между задачами черновики не затирали друг друга.
   - В **Работах и Пробниках**: код хранится под парой `(sessionId, taskId)` локально + улетает на сервер при отправке ответа и во время On-Demand Live-наблюдения учителя.
   - CSS-класс `.paste-marker-bg` в редакторе: у самого ученика в режиме решения он прозрачный (чтобы не пугать античитом), а в компоненте `ReadOnlyCodeViewer` у учителя подсвечивается заметным янтарно-красным фоном `bg-amber-500/20 border-b border-amber-500` с тултипом *«Вставлено из буфера обмена»*!

### 3.2. Полноэкранный Табличный процессор (`SpreadsheetModal` на базе Univer)
*(Рендерится лениво через `React.lazy` только на десктопе `>= 768px`).*
1. **Точка входа**:
   - У каждого прикреплённого файла с расширением `.xlsx`, `.xls`, `.ods`, `.csv` на карточке задачи отображаются две кнопки: **`[Скачать]`** и **`[Открыть в таблицах]`** (плюс кнопка открытия чистой книги в плавающем тулбаре рядом с «Редактор кода» и «Рисование»).
2. **UI огромной модалки**:
   - Разворачивается почти на весь экран (`fixed inset-3 z-50 rounded-2xl border bg-background shadow-2xl flex flex-col`) с затемнением фона.
   - В верхней панели модалки: название файла (`9.xlsx`), индикатор *«Сохранено локально»*, кнопка **«Сбросить к исходному файлу»** (с подтверждением) и крупный крестик закрытия **`✕`** (`Esc` закрывает модалку, если не активно редактирование ячейки).
3. **Локальная персистентность правок в IndexedDB**:
   - При первом открытии файла задачи исходный бинарник берётся из `FileCacheService` (OPFS), парсится через `SheetJS` в `IWorkbookData` и загружается в `Univer`.
   - Любые правки ученика (формулы `=ЕСЛИ(...)`, добавленные столбцы, заливка ячеек, сортировка) с дебаунсом `800ms` сериализуются (`workbook.save()`) в `IndexedDB` по ключу `sheet_state:{scope}:{taskId}:{fileId}`.
   - Когда ученик закрывает модалку крестиком (чтобы перечитать условие или вписать ответ) и снова нажимает «Открыть в таблицах» — **мгновенно открывается его сохранённое рабочее состояние** со всеми написанными формулами! А если нужно начать заново — кнопка «Сбросить к исходному файлу» очищает запись в `IndexedDB` и перечитывает чистый файл из OPFS.

### 3.3. Универсальный компонент задачи (`TaskCard`) и 4 типа ввода ответа
1. **Шапка карточки**:
   - Номер КИМ (`№24` или бейдж связки `№19–21`), название темы, цветной бейдж сложности (`Базовый` зелёный, `Средний` синий, `Сложный` оранжевый, `Гроб` фиолетово-красный), `#ID` с копированием ссылки, источник `source` (если не `null`) и всплывающее окно статистики задачи (процент решивших + мини-гистограмма попыток `attempts_histogram`).
2. **Условие (`MarkdownMathRenderer`)**:
   - Поддержка GFM-таблиц, блоков кода с подсветкой, встроенных формул `$...$` / `$$...$$` через KaTeX и галереи изображений `images` с зумом по клику (Lightbox).
3. **Блок ввода ответа (`AnswerInput`)**:
   - `single`: однострочный `Input` + отправка по `Enter`.
   - `pair`: два подписанных поля в ряд (`Файл А`, `Файл Б` или два числа).
   - `table`: аккуратная интерактивная сетка ячеек `rows × cols` с навигацией стрелками/`Tab`/`Enter` и поддержкой вставки многострочного вывода прямо из терминала Python (`Ctrl+V` автоматически раскладывает строки и числа по ячейкам таблицы!).
   - `triplet_19_21`: три визуально разделённых мини-блока `Задание 19 (1 балл)`, `Задание 20 (1 балл)`, `Задание 21 (1 балл)` внутри одной карточки.
4. **Поведение в Банке**:
   - Для гостя: вместо кнопки «Проверить» — кнопка «Войдите, чтобы проверить ответ» (`Link` на `/login`).
   - Для авторизованного: счётчик попыток; после верного ответа или `total_attempts >= 3` плавно раскрывается аккордеон **«Правильный ответ и разбор»** (`solution_md` + копируемый блок `solution_code`).

### 3.4. Главная ученика (`/`), Шапка ролей и Симулятор Пробника КЕГЭ
1. **Шапка (`Header.tsx`)**:
   - Навигация адаптируется под выбранный `viewMode`:
     - `student`: *Главная, Мои группы, Банк задач, Пробник ЕГЭ*.
     - `teacher`: *Мои группы, Мои задачи, Банк задач, Тарифы/Подписка*.
     - `admin`: *Задачи банка, Импорт CSV/ZIP, Темы, Подписки и Инвайты, Пользователи, Шкала ЕГЭ*.
   - Справа: компактный `SegmentedControl` переключения роли (виден только у `teacher` и `superuser`) + у `superuser` кнопка быстрого выбора пользователя для Impersonation (при активном Impersonation сверху горит заметная полоска *«Вы просматриваете сайт от имени Иван Петров (@ivan_inf) — [Выйти]»*).
2. **Главная страница ученика (`/`)** *(строго по ТЗ — всё кроме прогноза балла)*:
   - **Блок 1: Горящие работы и дедлайны** из групп ученика (карточки с таймером до дедлайна и кнопкой «Перейти к выполнению») + кнопка «Начать тренировочный вариант КЕГЭ (3ч 55м)».
   - **Блок 2: Тепловая сетка прогресса по номерам КИМ 1–27** (плитки 1..27, окрашенные по `success_rate` и числу решённых задач; клик ведёт в Банк с фильтром по этому номеру).
   - **Блок 3: Слабые темы** (топ тем с наибольшим баллом слабости `score`, требующих проработки).
   - **Блок 4: Персональная подборка задач на сегодня** (`weak_topic` + `adaptive_difficulty`).
3. **Симулятор Пробника и Работ (`/exam/$sessionId`)**:
   - Современный чистый интерфейс в текущей светлой/тёмной теме сайта.
   - Слева: фиксированная колонка номеров варианта (`1..18`, объединённая плитка `19–21`, `22..27`) с цветовой индикацией (серый — не открывал, контур — открывал без ответа, синий — ответ сохранён) + тикающий синхронизированный с сервером таймер.
   - По центру: активная задача + сохранение ответа одной кнопкой (с возможностью менять ответ сколько угодно раз до завершения экзамена в режиме `mock_exam`, либо по правилам `max_attempts` теста).
   - Поверх: привычный плавающий тулбар с Python IDE, Таблицами и Рисовалкой (в зависимости от `settings.tools_allowed`).
   - По завершении: красивый итоговый протокол с таблицей первичных баллов по каждому номеру (`0..29`), итоговым **тестовым баллом ЕГЭ (`0..100`)** и доступом к разборам.

### 3.5. ЛК Учителя: Live-матрица класса и Интерактивный Прокторинг-Таймлайн
1. **Группы и Инвайты**:
   - Плашка статуса подписки учителя (если истекла — аккуратный баннер Read-Only режима со ссылкой на продление, кнопки «Создать группу» и «Создать работу» задизейблены с пояснением, все прошлые данные полностью кликабельны).
   - Модалка приглашения учеников: короткая ссылка в 1 клик + огромный контрастный **QR-код** во весь экран для демонстрации классу с проектора.
2. **Гибкий Конструктор работы (`/groups/$roomId/create-work`)**:
   - Быстрые карточки пресетов (*Домашняя работа, Классная работа, Практика, Контрольная с прокторингом, Пробник КЕГЭ 235 мин*), которые предзаполняют форму `AssignmentSettings`, но позволяют поменять абсолютно любой тумблер вручную.
   - Корзина задач с drag-and-drop сортировкой позиций: подбор из Общего банка, из Личных задач учителя или кнопка «+ Создать свою задачу прямо в вариант».
3. **Live-матрица выполнения в реальном времени (`/groups/$roomId/assignments/$id`)**:
   - На маунте загружает `GET /assignments/{id}/matrix` в TanStack Query и отправляет в WS `teacher.watch_assignment`.
   - При каждом входящем `matrix.presence_patch` и `matrix.cell_patch` обновляется ровно нужная строка/ячейка без рефетча:
     - В колонке ученика живой индикатор: 🟢 *На вкладке (Задача №15, IDE открыта)* | 🟡 *Свернул вкладку 18 сек назад* | ⚪ *Офлайн* + бейджи-счётчики уходов с вкладки и вставок кода (`📋 2`).
     - Ячейки задач вспыхивают мягкой анимацией при приходе нового ответа (зелёный — полный балл, жёлтый — частичный балл 1/2, красный — 0 баллов, дробь попыток `2/4`).
     - В шапке каждого столбца автоматически пересчитывается живой процент решивших по классу.
4. **Детальная инспекция ученика (`StudentInspectDrawer` — открывается по клику на строку ученика)**:
   - При открытии отправляет `teacher.watch_student_live`, активируя живой поток с фронтенда ученика, при закрытии — `teacher.unwatch_student_live`.
   - **Вкладка 1 — Live-наблюдение за кодом**: в реальном времени (с задержкой ~350 мс) показывает, какую задачу сейчас открыл ученик, его текущий код в read-only Monaco с позицией курсора, **подсветкой всех вставленных из буфера диапазонов `paste_ranges`** и живым хвостом вывода терминала!
   - **Вкладка 2 — Детальный интерактивный Таймлайн (`ProctoringTimeline`)**:
     - Горизонтальная масштабируемая шкала времени от старта до сдачи работы (с поддержкой зума колесом мыши).
     - Фоновая дорожка фокуса: зелёные интервалы (работал на вкладке) и красные интервалы с точной длительностью (`Ушёл со вкладки: 1 мин 14 сек`).
     - Дорожка задач: на какой задаче сколько времени провёл.
     - Кликабельные маркеры событий: отправка ответа (с превью ответа и результата), запуск кода, открытие таблиц, вставка кода `insert_in_ide` (по клику раскрывается карточка с точным временем, количеством символов и превью вставленного куска!).
